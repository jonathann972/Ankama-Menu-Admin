======================================================================
2. ÉTAT FONCTIONNEL ACTUEL
======================================================================

- Écho existe avec l’ID objet 32760.
- Type d’objet : Anomalie (type 290).
- Rareté : Épique.
- Les exemplaires possèdent des jets individuels persistants :
    - effet 3100 : chance de répétition, stockée en dixièmes ;
    - effet 3101 : puissance de l’Écho en pourcentage.
- L’effet 3102 marque temporairement, côté client, l’exemplaire actif.
- Le véritable UID actif est sauvegardé côté serveur dans :
    characters.ActiveAnomalyItemUid
- Activation disponible côté serveur :
    /anomaly <UID>
- Désactivation disponible côté serveur :
    /anomaly off
- L’effet de combat d’Écho est déjà fonctionnel.
- Le serveur World compile et fonctionne.

Une interface de secours est actuellement déployée. Elle est dessinée
directement en ActionScript/Flash, sans XML, afin d’éviter le blocage à 48 %.
Elle confirme que le point d’entrée du module et les interactions fonctionnent.

======================================================================
3. PROBLÈMES DE L’INTERFACE ACTUELLE
======================================================================

- Le bouton Anomalies apparaît pendant l’écran de chargement.
- Le bouton est positionné avec des coordonnées fixes.
- Il ne peut pas être déplacé par le joueur.
- Sa position n’est pas sauvegardée.
- Il ne s’intègre pas réellement au HUD natif de Dofus.
- Le panneau est un prototype brut, très éloigné de l’image de référence.
- Les textes se chevauchent ou sont tronqués.
- L’icône d’Écho n’est pas affichée dans le panneau.
- Il manque les cartes, les slots, les cadres, les filtres et le décor central.
- Les accents ont été temporairement retirés de certains textes.
- Le panneau ne se redimensionne pas encore proprement avec la fenêtre.

======================================================================
4. CONTRAINTE CRITIQUE : CHARGEMENT À 48 %
======================================================================

Deux tentatives ont provoqué un chargement infini à 48 % :

1. Modification/recompilation de BannerMenu et de plusieurs classes natives.
2. Enregistrement d’un module personnalisé chargeant ses XML au démarrage.

La version actuellement fonctionnelle contourne le problème :

- le module Anomalies est enregistré dans com.ankamagames.dofus.Modules ;
- il ne déclare aucun fichier UI XML dans son fichier .dm ;
- il ne charge aucun asset ou template pendant la phase des 48 % ;
- son interface est créée après l’initialisation des modules.

Règle de développement pour la reprise :

NE JAMAIS déployer en une seule fois une modification du registre, du menu
natif, des XML et des classes UI. Procéder par étapes testables et conserver
un SWF fonctionnel après chaque étape.

La recompilation complète de BannerMenu doit être évitée autant que possible.

======================================================================
5. COMPORTEMENT ATTENDU DU BOUTON
======================================================================

- Le bouton ne doit apparaître qu’une fois le personnage effectivement en jeu.
- Il ne doit jamais apparaître sur :
    - la connexion ;
    - la sélection du serveur ;
    - la sélection du personnage ;
    - l’écran de chargement à 48 %.
- Le créer à la réception de GameStart, ou après confirmation que le HUD
  principal est chargé.
- Le masquer/détruire lors de la déconnexion ou du retour à la sélection.
- Le clic ouvre et ferme le panneau Anomalies.
- Ajouter une infobulle « Anomalies » au survol.
- Utiliser l’icône violette/vortex déjà créée.
- Le bouton doit être déplaçable par glisser-déposer.
- Sa position doit être limitée aux dimensions visibles de la fenêtre.
- Sa position doit être sauvegardée avec SystemApi.setData.
- La position doit être liée au compte ou à l’ordinateur, pas à une coordonnée
  absolue fragile.
- Après redimensionnement, conserver une position relative ou replacer le
  bouton dans la zone visible.
- Prévoir une commande ou un moyen de réinitialiser sa position.

Position par défaut suggérée : près des raccourcis du HUD en bas à droite,
sans couvrir la barre de sorts, le chat ou la mini-carte.

L’image de référence sert de direction artistique, pas de fichier à copier

Disposition générale :

7. ARCHITECTURE RECOMMANDÉE
======================================================================

Conserver le registre minimal qui fonctionne actuellement, mais ne plus créer
le bouton dès la méthode main() du module.

Étape A — cycle de vie fiable :

- écouter le hook GameStart ;
- créer le bouton uniquement à ce moment ;
- gérer la destruction du bouton au changement de contexte ;
- vérifier plusieurs connexions/déconnexions sans doublon.

Étape B — bouton mobile :

- PRESS : mémoriser le point de départ ;
- MOUSE_MOVE : déplacer le bouton ;
- RELEASE : borner et sauvegarder la position ;
- distinguer un clic d’un déplacement ;
- restaurer la position au prochain GameStart.

Étape C — panneau Flash stable :

- rester temporairement sur des DisplayObject Flash directs ;
- créer des composants réutilisables : Panel, Card, Slot, StyledLabel,
  StyledButton et IconView ;
- corriger complètement mesures, alignements, retours à la ligne et masques ;
- charger les images uniquement après GameStart ;
- prévoir un fallback vectoriel si une image ne charge pas.

Étape D — rapprochement du style Dofus :

- réutiliser prudemment les textures déjà disponibles dans le thème ;
- ne charger qu’une ressource à la fois et tester après chaque ajout ;
- ne pas réactiver les XML de module tant que leur compilation en .d2ui et
  leur cycle de chargement ne sont pas maîtrisés ;
- si une intégration XML est retentée, commencer par un XML vide minimal,
  puis ajouter un seul composant à la fois.

11. PROCÉDURE DE DÉVELOPPEMENT OBLIGATOIRE
======================================================================

Pour chaque étape :

1. Partir du dernier SWF confirmé fonctionnel.
2. Sauvegarder le SWF avant modification.
3. Modifier une seule responsabilité à la fois.
4. Compiler dans un fichier candidat distinct.
5. Réexporter les classes modifiées avec JPEXS pour les vérifier.
6. Comparer les classes réellement modifiées.
7. Déployer seulement après validation statique.
8. Fermer complètement Dofus.
9. Tester la connexion et le passage des 48 %.
10. Tester le bouton et le panneau.
11. Marquer le candidat comme stable avant de poursuivre.

En cas de blocage à 48 % : restaurer immédiatement la sauvegarde stable et
ne pas empiler une nouvelle correction sur le SWF défectueux.
